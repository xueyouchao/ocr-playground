OCR-playground (CPU/GPU)

Every pane is a parser run the way its own project intends. The baseline is an open-source, text-based CPU pipeline (LiteParse + Tesseract): no GPU, a couple of seconds per page, and a predictable cost, so it is the reference the other panes are read against. The comparison is open-source VLM-based OCR (Chandra OCR 2, Nemotron Parse, GLM-OCR, Unlimited-OCR, MinerU 2.5), which reads handwriting and tables noticeably better but needs a GPU. General-purpose vision-language models such as Anthropic's Claude Opus were not chosen: their per-page cost and latency are far higher than either local option, which would make a six-page, every-parser demo slow and expensive to run.

Read your own document A PDF (up to 5 pages) or one image. Chandra OCR 2 is the default: layout-rich markdown with tables, at about a minute a page, and its GPU scales to zero, so the first upload after idle also waits for boot. GLM-OCR is the faster warm path (about 5 seconds a page) and reads handwriting best. LiteParse + Tesseract is CPU-fast, but weaker on handwriting.

This page, every parser

There is no accuracy score here. The numbers are counts: characters (table markup included, so a table parser's count runs high) and the tokens it wrote, with how many are numbers. A dictionary-based score was removed because on this document it was measuring the wrong thing — page 4 is 77% numbers, and its remaining words are column abbreviations (“CLD”, “ABV”, “TDME”) that no dictionary contains, so a correct reading scored 30%. Judging accuracy needs a hand-transcribed ground truth, which these pages do not have. Compare each pane against the scan.
