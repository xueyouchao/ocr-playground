One scanned form, every document parser

Six pages from the demo corpus: one printed page and five handwritten forms. Each pane is a parser run the way its own project intends — native pipeline where it has one, LiteParse + Tesseract as the baseline. Text is what the parser emitted; preview renders that same output so you can judge it against the page on the left. A pane that says not run had no endpoint; it is not a failure.

Read your own document A PDF (up to 5 pages) or a single image. GLM-OCR is the default and reads handwriting and tables best, but it runs on a scale-to-zero GPU: after the site has been idle, the first upload can take several minutes while the model boots, before it reads a single page. LiteParse + Tesseract is the fast option — a couple of seconds per page on this server's CPU — and visibly weaker on handwriting.

This page, every parser

There is no accuracy score here. The numbers are counts: characters (table markup included, so a table parser's count runs high) and the tokens it wrote, with how many are numbers. A dictionary-based score was removed because on this document it was measuring the wrong thing — page 4 is 77% numbers, and its remaining words are column abbreviations (“CLD”, “ABV”, “TDME”) that no dictionary contains, so a correct reading scored 30%. Judging accuracy needs a hand-transcribed ground truth, which these pages do not have. Compare each pane against the scan.
